# Nebras documentation preparation

Prepare Vue documentation for an initial embedding run and future incremental ingestion. This repository does not embed text, upload vectors, or delete Qdrant points.

## Run

Use Node.js 20 or later and a clean checkout of `Nebras-Open-Finance/community-standards`.

```sh
npm install
npm test
npm run prepare:docs -- --source-root ../community-standards --output ./runs/baseline
```

The output directory must not already exist. Each run writes `parsed-output/`, `chunk-output/` and `manifest.json` inside it. The existing checked-in output directories contain the older schema and are not regenerated by this change.

For a selected set of pages, create a JSON file:

```json
["src/pages/tech/tpp-standards/production/testing-certification/optional/overview.vue"]
```

```sh
npm run prepare:docs -- --source-root ../community-standards --output ./runs/selected --files ./files.json
```

`bash src/scripts/parse-chunk.sh` accepts the same options. Full mode scans Vue pages, excluding `_shared` directories. It does not define the approved pilot corpus: it can include internal and non-developer pages. Use a reviewed file list for the pilot.

## Chunk contract (schema 2)

- `id`: deterministic UUIDv5 from source repository, document ID and chunk key. Use this as the Qdrant point ID.
- `document_id`: existing document path. Use this to filter all points belonging to a document.
- `chunk_key`: intro, navigation target, or section identity plus duplicate occurrence. No document-wide counter is used for identity.
- `content_hash`: SHA-256 of the exact UTF-8 `text` sent for embedding, including its breadcrumb.
- `text`: embedding input, also retained in the Qdrant payload.
- `metadata`: source repository/file/commit/hash, page URL, documentation version, parser/chunker versions, import specifiers and extraction warnings.

Section identity prefers explicit anchors. Renaming unanchored headings or inserting duplicate headings may change keys. The later engine should reuse vectors by content hash when keys move, while ensuring the embedding model and dimensions match. A metadata-only change does not require embedding again.

Page URLs are derived from document IDs for ordinary routes. They are candidates, not HTTP-validated canonical URLs. Dynamic bracket routes and `_shared` paths have no inferred URL. Navigation destinations are retained as `navigation_url`; `url` identifies the containing document. Anchors are separate and must be validated before linking to a section.

## Future Qdrant uploader and incremental engine

Upload each chunk as `{ id: chunk.id, vector, payload: chunk }`. Also persist the actual embedding model, output dimensions and embedding configuration. Query document points by `document_id`, or source points by `metadata.source_repo` and `metadata.source_file`. Create keyword payload indexes for those filter paths.

After a successful website deployment, compare source commits and process only changed pages plus pages affected by shared dependencies. Reuse identical text embeddings, embed changed/new text, and remove obsolete point IDs only after successful preparation and writes. Handle deleted/renamed source files explicitly from Git's old and new paths. Save the successful ingestion checkpoint in the engine, after Qdrant reconciliation.

`manifest.json` records preparation results and chunk hashes. A missing file, failed parse, missing URL or zero-chunk output must not be interpreted automatically as a deletion. Only a complete, reviewed manifest should enter an initial ingestion run. Its status is not a Qdrant ingestion checkpoint.

## Extraction limits

The parser extracts static Vue content. Import specifiers are recorded for later dependency resolution; they are not a resolved or transitive file-to-page map. Imported components, dynamic content, generated API schemas, field mappings and Markdown pages still need extraction work. Review warnings and zero-chunk outputs before the baseline embedding. This change supplies update metadata; it does not close those coverage gaps.

`injection.js` is a legacy parser and is not used by this pipeline.
